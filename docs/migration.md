# 已有项目逐页迁移

目标：**一次只换一页**，随时可以停下或回退，业务功能和交互语义保持不变。

## 0. 先确认三件事

1. 目标项目用什么技术栈、能不能直接在入口引一个 CSS 文件（不能就先从 `tokens.css` 手动映射）。
2. 它现在有没有全局样式（`reset.css`、UI 框架主题、Tailwind preflight）。有的话记下来，后面逐条对冲突。
3. 是否已有自己的设计令牌。有则先把本系统的 `--c-*` / `--sp-*` 映射到它的命名，避免两套变量并存。

## 1. 加依赖、只引样式

```bash
npm install file:../self-ui-style#v0.8.1
```

```js
// 入口
import '@self/ui-style/theme.css';
import { DS } from '@self/ui-style';
```

先不要动任何页面，确认构建通过、首屏没有变化（此时没有任何元素带 `.ds-theme`，样式不会生效）。

## 2. 选一个代表性页面

选**有表单 + 列表 + 一个抽屉/弹窗**、但依赖不深的页面，通常比首页更适合验证。

在该页最外层容器挂主题：

```html
<div class="page-dashboard ds-theme">
```

第一轮只做一件事：把页面背景、字色、基础字号交给主题，确认没有横向溢出、没有字体跳变、没有把业务组件顶飞。此时旧按钮和旧输入框仍是原样，属于正常状态。

## 3. 按「由外到内、由静态到交互」替换

| 顺序 | 替换内容 | 验收点 |
| --- | --- | --- |
| 1 | 页面级容器、卡片、分隔线 | 阴影/圆角/间距是否与设计稿一致 |
| 2 | 按钮（`btn` → `ds-btn` + `ds-btn-primary` 等） | 默认/悬停/按下/聚焦/禁用/加载六态 |
| 3 | 表单控件（`input`/`select`/`textarea` 换成 `ds-input` 等） | 焦点环、错误态、只读态 |
| 4 | 状态标签、进度、分段筛选 | 状态不只靠颜色，图标 + 文字齐全 |
| 5 | 表格 | 长标题换行、列宽、行内操作命中区 |
| 6 | 抽屉/弹窗与 Toast | Esc、Tab 焦点锁、关闭回焦、失败可重试 |

每换一层截一次图（同一视口、同一数据），和替换前对比。出现差异先判断是**样式问题**还是**业务结构问题**，不要用 `!important` 压过去。

## 4. 处理冲突

- 旧全局样式命中同类元素（如 `button { border-radius: 999px }`）：在迁移范围内加一层 `:where(.ds-theme)` 之前的选择器收窄，或把旧规则限制在未迁移的容器上。
- Tailwind / UI 框架：与本系统类名不冲突（全部 `ds-` 前缀），但 preflight 可能重置 `svg`、`table`、`input`。在主题容器上补回必要属性即可，不要全局关掉 preflight。
- `body` 背景：本系统的点阵背景挂在 `.ds-theme` 上。若页面容器不占满视口，应加 `min-height: 100vh`，而不是把背景改到 `body`。
- 层级：遮罩 `--z-scrim: 40`、抽屉 `--z-drawer: 50`、Toast `--z-toast: 60`。与项目自身的弹层冲突时改这三个 token，不要就地写魔法数字。

## 5. 验收清单

- [ ] 1280×800 / 1440×900 / 1920×1080 无横向溢出，主要操作在首屏可见
- [ ] 迁移前后同视口截图对比，差异都是预期内的
- [ ] 键盘：Tab 顺序合理，焦点环可见，抽屉内焦点不逃逸，Esc 可关闭并回焦
- [ ] 对比度：正文 ≥ 4.5:1，辅助文字 ≥ 4.5:1（本系统自检脚本可复用）
- [ ] 长标题、空数据、加载、失败重试都有明确表现
- [ ] 业务交互语义未变（提交、校验、跳转、权限判断仍在）

## 6. 推广到其他页面

一个页面验收通过后，把「容器类 + 组件类映射表」沉淀成项目内的对照表（旧类名 → 新类名），后续页面按表替换，最后再删除旧样式。不要一次性全站替换：视觉回归和业务回归会同时失控。

## 7. 回退

迁移以页面为单位提交，回退只需撤掉该页的 `.ds-theme` 容器类与组件类替换，不影响其他页面。
