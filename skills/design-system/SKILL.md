# 方寸设计系统 · Agent 规则

这是可跨项目复用的视觉语言与基础 UI 起点，不是覆盖所有产品形态的完整通用组件库。使用时保留消费项目业务结构与交互语义，按需组合基础组件。

## 先用，后写

- 先读 `docs/react-components.md` 的组件清单与稳定性。React 项目可选用 `@self/ui-style/react`（当前整体为实验中）；框架无关项目使用 `src/ui/ui.css` 的 `.ds-*` 类，原生交互工具在 `src/ui/ui.js`（`DS.toast`、`DS.drawer`）。
- 参考页面：`index.html`（工作台，业务密度基准）、`examples/components.html`（组件全状态）。
- 数值只从 `src/tokens/tokens.css` 取，不要凭感觉写新的颜色、圆角、阴影。确实缺变量时，先加 token 再用。
- 不要重做视觉。缺组件时按同一套规则扩展（见下方「扩展」），并把新组件加进 `examples/components.html`。

## 工作流程

1. **读目标项目**：技术栈、目录结构、全局样式（reset / UI 框架 / Tailwind）、已有设计令牌。先判断能不能直接引 CSS 文件；不能就先映射 tokens。
2. **加载本系统**：读 `DESIGN.md` 的变量与规则、`src/tokens/tokens.css`、`src/ui/ui.css`，必要时看 `docs/integration.md`。
3. **优先复用**：把业务标记映射到 `.ds-` 类；只在业务层写布局与业务状态，不复制组件样式。新增组件必须只用现有 tokens。
4. **保留业务语义**：不要为了视觉改表单字段、提交逻辑、权限判断、路由、埋点；交互语义（校验时机、失败重试、焦点顺序）按目标项目原样保留。
5. **先迁一页**：选有表单 + 列表 + 抽屉的代表页，迁移后同视口截图对比，确认视觉变化都是预期内的，再扩面。
6. **处理样式冲突**：主题只作用于挂了 `.ds-theme` 的容器；不要覆盖 `:root`、`body`、`*`；不要用 `!important` 压旧样式，先收窄旧选择器或作用域。
7. **支持范围**：React 18+ 有实验中 TS 组件层；Vue/Svelte/原生目前复用 tokens、CSS 类与规格（`DESIGN.md`），没有官方框架封装。不要把 React 组件或 DOM 工具硬套到不兼容环境。

## 视觉硬规则

- 浅色底 `#f7fafc`，单一强调色 `#6d5dfc`（文字用 `#4b3fd0`）；状态色 success `#2f6b4f`、warn `#7d5f16`、danger `#96403e`。
- 圆角：控件 8px、徽标 6px、卡片/面板 16px、抽屉 16px、进度槽胶囊。禁止把按钮做成胶囊。
- 阴影是双向的：凸起 = 暗部 `+X +Y`、亮部 `-X -Y`（`8/16` 为主，`4/8` 给小控件）；内凹 = `inset`（输入 `3/6 + -6/12`，聚焦收到 `1/2` 并加 1px 强调描边）。
- 层次靠背景明度 + 阴影 + 1px 细线，不靠大面积渐变、毛玻璃、发光。
- 点阵细节只放在品牌标记、主按钮图标、抽屉抓手上；页面底纹是 22px 单色点阵，不要叠加第二种纹理。
- 默认字体在线加载 Noto Sans SC / JetBrains Mono，并保留系统回退；除非目标项目明确要求离线运行或跨设备字体一致，否则不内嵌字体文件。
- 间距 4px 体系（8/12/16/24/32/48），行高 ≥ 1.4，正文 14px，辅助 12–13px。表格长标题完整换行并允许行高自动增加，不能为了固定行高造成文字重叠或截断。
- 状态必须同时有颜色 + 图标 + 文字，不能只靠颜色。
- 交互：默认浮起 → 悬停收回一档 → 按下内凹；过渡 300ms ease-in-out；`prefers-reduced-motion` 下降为瞬时。

## 可访问性底线（不可为了好看牺牲）

- 正文对比度 ≥ 4.5:1，本系统正文实际 12:1；禁用态除外，但禁用态必须有非颜色线索。
- 键盘可达：`Tab` 焦点环 2px 强调色；抽屉打开聚焦首字段、`Tab` 不逃逸、`Esc` 关闭并回焦触发元素。
- 图标按钮必须有 `aria-label`；纯装饰图标 `aria-hidden="true"`；抽屉 `role="dialog" aria-modal="true"`。

## 扩展组件

1. 复用现有 token；需要新值先写进 `tokens.css` 并说明用途。
2. 类名 `ds-` 前缀 + BEM 风格后缀（`ds-tag--warn`），状态类 `ds-is-open` / `ds-is-invalid`。
3. 样式放进 `src/ui/ui.css`，作用域写在 `.ds-theme` 之下。
4. 在 `examples/components.html` 加一个展示区块，覆盖默认/悬停/聚焦/禁用/加载（能覆盖到的话）。
5. 跑 `npm run verify`；改动视觉则同时跑 `npm run screenshot`，并更新 `CHANGELOG.md`。

## 禁止

- 不引入第二套配色/圆角/阴影体系，不引入新的 UI 框架覆盖本系统。
- 不在业务页面里复制粘贴组件 CSS，不写行内 `style` 代替组件类（布局微调除外）。
- 不把 `ds-` 组件与业务 API、路由、全局状态耦合；`DS.*` 工具只处理 DOM 行为。
- 仅使用 package exports 的公开入口，不从 `src/` 内部路径深导入；React 显式加载 `@self/ui-style/react/style.css` 并置于 `DesignSystemProvider` 内。
- 组件尚未实现或状态非稳定时，如实记录为实验中/未实现，不在消费项目复制源码制造分叉。
- 不声称验证过未验证的内容（真实后端、Safari/Firefox、屏幕阅读器）。
